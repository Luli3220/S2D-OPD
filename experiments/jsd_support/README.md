# Fixed-rollout JSD support audit

This independent diagnostic answers how JSD resolution changes selection masks.
The offline `run.sh` pipeline does **not** train a model or change Direct-OPD
reward candidates. Its code and output live here. A separate `train.sh` launcher
below runs the representative training ablation using independent scoring support.

## Protocol

1. Sample 128 prompts from the **processed training parquet**, filtering prompts
   longer than 1,024 tokens, using a saved seed. Apply the student's existing chat
   template exactly as the training text dataset does. Generate four responses per
   prompt, temperature 1, top-p 1, no top-k sampling limit, maximum 2,048 tokens.
2. Freeze the exact prompt and response **token IDs** in `bank.jsonl`. Each K is
   scored on these same IDs and checkpoints. No decoding/re-tokenizing or new
   generation occurs during scoring. Keep sampled EOS tokens; exclude padding.
3. For every response position, obtain the student's nested top-128 IDs. Compute
   teacher/reference probabilities over their complete output vocabulary. For
   K=8,16,32,64,128, retain the first K candidates and collapse the remaining
   probability into a single tail bucket. Also compute full-vocabulary JSD without
   collapsing the tail. The teacher/reference probabilities are shared by all K.
4. Select `ceil(0.10 * response_length)` positions **within each response**, using
   the same stable ascending sort and upper-tail tie rule as the existing actor.
   Masks do not affect any model forward or training objective.
5. Compare masks and scores to the full-vocabulary reference. Average response
   metrics within prompt, then average over prompts. Bootstrap whole prompts
   (2,000 repetitions, percentile 95% intervals), never independent tokens.

Run this diagnostic once using the **initial Qwen3-1.7B student**. All scoring
resolutions share exactly one frozen bank generated by that checkpoint. No
intermediate training checkpoint or additional training run is required.

## Launch on the prepared server

The existing environment must provide PyTorch, Transformers, vLLM, PyArrow and
NumPy. Supply the local HF-format initial student and teacher/reference models.

From the repository root:

```bash
export PYTHON_BIN="$(command -v python)"
export STUDENT_MODEL_PATH="/path/to/Qwen3-1.7B"
export REWARD_MODEL_PATH="/path/to/JustRL-DeepSeek-1.5B"
export TEACHER_REF_MODEL_PATH="/path/to/DeepSeek-R1-Distill-Qwen-1.5B"
export TRAIN_DATASET="/path/to/processed/skywork-or1-math-dapo-original.parquet"

STAGE=initial bash experiments/jsd_support/run.sh
```

Generation uses one GPU by default (`ROLLOUT_TP=1`); change ROLLOUT_TP if needed.
Scoring automatically uses all visible GPUs as independent replicas, one frozen
response per forward on each rank. `SCORE_GPUS` can limit the replica count.
The script does not start/stop Ray and does not kill existing jobs. Only run on
available GPUs; the script does not schedule around other workloads.

Defaults match the repository's text rollout lengths/sampling settings. Optional
overrides include `NUM_PROMPTS`, `N_RESPONSES`, `SAMPLE_SEED`, `MAX_PROMPT_LENGTH`,
`MAX_RESP_LENGTH`, `TEMPERATURE`, `TEACHER_TEMPERATURE`, `JS_TOP_FRACTION`,
`CHAT_TEMPLATE_KWARGS` (JSON), `OUTPUT_DIR`, and `BOOTSTRAP_REPEATS`.

## Precision and memory

Scoring defaults to **float32 parameters and logits** with HF SDPA, rather than
the trainer's bf16 autocast. This makes full/coarse JSD share a precise numerical
reference; it is not a claim of bitwise equality with training masks. All K use
the same inference precision. `SCORE_DTYPE=bfloat16` reduces parameter memory;
probability normalization and JSD calculations still use fp32. Record the chosen
precision. `SCORE_ATTENTION=flash_attention_2` requires a
half-precision dtype; the default SDPA requires no Flash Attention installation.

Each scoring GPU holds student, teacher and reference models (about 20 GB of
float32 parameters for the default model sizes, plus activations/workspace).
The scorer calls the Qwen2/Qwen3 transformer backbone once per model and response,
then projects response hidden states through the LM head in 64-position chunks.
It never retains a `[responses, tokens, vocabulary]` bank of logits. Reduce
`CHUNK_POSITIONS` if needed. Scoring supports Qwen2/Qwen3 causal LM architectures.

Teacher/reference token mappings and output vocabulary sizes must match.
Like the existing Direct-OPD pipeline, prefixes are passed to both teachers as
raw student token IDs. Student/teacher shared-token ID discrepancies are recorded
in each shard's `token_id_audit`; no silent tokenizer remapping is performed.

## Outputs and interpretation

Default output: `experiments/jsd_support/outputs/<STAGE>/` (git-ignored).

- `bank.jsonl`, `bank.manifest.json`: exact tokens, sample/row IDs, finish reasons,
  data checksum, model identity, generation settings and software provenance.
- `scores/scores.rank*.npz` and `.json`: per-token scores, response offsets,
  replica metadata and checksums. A completed matching bank/shard is reused;
  incompatible outputs fail rather than overwrite. Use a fresh directory after
  changing model, generation or scoring settings. Weight-file identities include
  filename/size/mtime; full weight contents are not hashed.
- `analysis/summary.csv`: per-K prompt-macro means, 95% intervals and the number of
  prompts with defined values. `overlap = |M_K intersect M_full| / |M_full|`.
  `retained_full_jsd_ratio` is full-JSD mass captured by M_K divided by that
  captured by M_full. Its ceiling is one, since the masks have equal budgets.
- `analysis/per_response.csv`: raw metrics, actual token/kept counts, random-mask
  expected overlap, absolute JSD error and ties at the selection boundary.
- `analysis/pairwise_mask_overlap.csv`: token-budget-weighted overlap across every
  pair of scoring resolutions (different aggregation from prompt-macro summary).
- `analysis/token_scores_and_masks.npz`: all token scores and boolean masks in
  original bank order, with offsets, IDs and column labels; no pickle required.
- `analysis/analysis_manifest.json`: settings, aggregation definition and provenance.

Spearman is undefined for a constant score vector or fewer than two positions.
Captured-mass ratios are undefined if the full reference has zero selected mass.
These values are `nan` in CSV and excluded with explicit defined-prompt counts.
A one-prompt sample has no bootstrap interval. Short-response rounding means
the actual retained percentage and chance overlap can exceed 10%.

## Individual stages

```bash
python experiments/jsd_support/audit.py generate --help
python experiments/jsd_support/audit.py score --help
python experiments/jsd_support/audit.py summarize --help
```

`summarize` needs only NumPy and Python; it can be rerun locally on downloaded
bank + score shards. Supply `--bank /new/location/bank.jsonl` after relocating
results; the checksum is still verified. Never edit the bank or its checksum.

## Training check: reward K=16, scoring K=8 or 64

Use the same JustRL/Qwen3-1.7B models, processed training data, seed and training
settings as the existing K=16 baseline. Set the existing training variables to
their actual locations. Note that `ACTOR_MODEL_PATH` is the training variable;
the offline tool instead uses `STUDENT_MODEL_PATH`.

```bash
export PYTHON_BIN="$(command -v python)"
export ACTOR_MODEL_PATH="/path/to/Qwen3-1.7B"
export REWARD_MODEL_PATH="/path/to/JustRL-DeepSeek-1.5B"
export TEACHER_REF_MODEL_PATH="/path/to/DeepSeek-R1-Distill-Qwen-1.5B"
export TRAIN_DATASET="/path/to/processed/skywork-or1-math-dapo-original.parquet"
export VAL_BEFORE_TRAIN=False

bash experiments/jsd_support/train.sh 8
bash experiments/jsd_support/train.sh 64
```

These are two full training runs using the existing default 8-GPU launcher and
separate experiment names/checkpoint/log directories. Reward/update top-k stays
at **16**. JSD ranks positions within each response, retains the highest **10%**,
and masks **both** reward and anchor KL. Other hyperparameters, validation and
checkpoint cadence, and adaptive KL use the original JustRL launcher defaults/
environment; preserve the matched baseline's settings and actual seed setup.
The launcher does not invent a new seed mechanism. The commands are sequential;
parallel jobs need separate resources and isolated Ray runtimes as for existing runs.

Main option: `JSD_SCORE_TOP_K` maps to `actor.jsd_score_top_k`. The default
**null** preserves existing behavior. Numeric overrides require FSDP/FSDP2
Direct-OPD (`delta_opd`, `only_stu`), the JSD divergence selector and filtering.

- Scoring K <= reward K slices the existing sorted student candidate support and
  teacher/reference log-probs, without additional model forwards.
- Scoring K > reward K uses a separate batch for three additional **no-grad**
  student/teacher/reference forwards on the same sampled states. Only the two
  teacher-side scoring tensors enter JSD computation; they are freed before
  actor updates. Original reward IDs, weights, reward tensors, candidate metrics,
  and the adaptive-KL reward statistic remain on top-16. In particular, reward
  IDs are not replaced by a prefix of top-64: different `topk` calls may resolve
  bf16 ties differently.

Training preserves the existing parameter dtype and bf16 autocast, unlike the
offline fp32 diagnostic. K=64 costs extra forward time and candidate buffers but
does not retain full-vocabulary scoring distributions across the rollout.

Check `jsd_support/reward_k=16`, `jsd_support/score_k=8` or `64`, and
`jsd_support/extra_scoring_pass=0` or `1`. Reward/KL keep ratios should both be
approximately 0.10, allowing per-response rounding. `train.sh 16` is also
available as a matched control and performs no additional scoring.
